# Phase 05-B2.1 — Authentication Core: Report

Base: Phase 05-B1 (`c19e83f7ded1ec2a6e4b0daa38ee6e29cfde3370`), branch `main`.
Scope: Bearer-token authentication only. No git commit / push / PR was made. Android repository untouched.

## Implemented

- Bearer authentication on `POST /v1/translate` (`Authorization: Bearer <token>`; scheme case-insensitive, exactly one space, one non-empty token without whitespace).
- Client token read from environment variable `GATEWAY_CLIENT_TOKEN` through the existing B1 `EnvSecretProvider` / `Secret` wrapper (value never serialised, logged or returned).
- Missing header, malformed header and wrong token all return **401** `UNAUTHORIZED` with one identical message, plus `WWW-Authenticate: Bearer` and `Connection: close`.
- Secure comparison: SHA-256 digest of both values + `crypto.timingSafeEqual` (equal-length inputs, so length differences do not throw or short-circuit).
- Authentication runs **before** the route handler: on failure no body parsing, no validation and no translation provider call happens.
- `GET /health` unchanged and public.
- Startup: in `NODE_ENV=production`, a missing / empty / whitespace-only / malformed `GATEWAY_CLIENT_TOKEN` makes startup fail (`exit 1`, message names the variable only). `buildApp` additionally refuses a production config without enabled auth (defence in depth).
- Development / test: when the token is unset, authentication is **not enforced** (keeps B1 behaviour and B1 tests unchanged); a warning is logged at startup. A token that is set but malformed fails in every environment.
- Logging: failures log only `{requestId, reason: missing|malformed|invalid}`; headers and tokens are never logged.
- `.env.example`: variable name `GATEWAY_CLIENT_TOKEN=` added, empty.
- B1 architecture kept (config → composition root → HTTP infrastructure; provider port untouched). No new dependencies.

- Valid token → authorized (provider called exactly once); lowercase `bearer` scheme accepted
- Missing token → 401, provider not called
- Invalid token (wrong, prefix, longer, upper-cased, 1 char) → 401, provider not called
- Malformed header (`Basic …`, `Bearer`, `Bearer `, double space, extra part, no space, bare token, empty, `Bearer a b`) → 401, provider not called
- Auth precedes body parsing / validation / content-type checks (bad JSON, `{}`, text/plain without token → 401)
- Authorized request still receives normal 400 validation errors; valid token without provider → 501 (no fake success); no token + no provider → 401 not 501
- Responses and logs contain neither the configured nor the submitted token; failures are logged by reason
- `/health` unchanged without token; unknown route still 404
- Config: production missing / empty / whitespace-only / whitespace-containing token fails and does not echo the value; production valid token enabled; dev/test unset or empty → not enforced; dev with token enforced; token absent from JSON/inspect output of the auth config; `buildApp` refuses production without auth
- Auth not configured: requests not blocked, stray header ignored

Manual smoke test of the real process: production without token → exit 1; with empty token → exit 1; with token: `/health` 200, no header 401, wrong token 401, correct token + empty body 400 (reached validation); token string occurs 0 times in the process log.

## Known Limitations

- Development/test with no token set serves `/v1/translate` unauthenticated (deliberate, to keep B1 dev behaviour; the dev default bind is 127.0.0.1).
- Single shared token: no rotation, no multiple tokens, no per-client identity.
- No minimum length / entropy check on the token (only printable ASCII, no whitespace). Use a long random value.
- No rate limiting, so repeated guessing is not throttled (B2.2+ scope, intentionally excluded).
- Route and method are resolved before authentication, so an unauthenticated `GET /v1/translate` gets 405 and unknown paths 404 (no information beyond the public route list).
- `ARCHITECTURE.md`, `SECURITY-NOTES.md`, `TEST-REPORT.md` and `CHANGED_FILES.md` (B1 documents) were not edited and still describe the B1 state; only `README.md` was updated.
